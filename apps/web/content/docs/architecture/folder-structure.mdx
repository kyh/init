title: "Folder Structure"

Init is a Turborepo monorepo with clear separation between applications and shared packages. Apps consume packages; packages never depend on apps.

## Overview

```
init/
├── apps/
│   ├── web/               # Next.js 16 web app
│   ├── mobile/            # Expo mobile app
│   ├── extension/         # Chrome extension (WXT)
│   └── desktop/           # Electron desktop app
├── packages/
│   ├── auth/              # Client-safe auth helpers: role permissions, slugify
│   ├── contract/          # oRPC contract: procedure inputs, outputs, errors
│   ├── service/           # oRPC implementation of the contract + better-auth
│   ├── db/                # Drizzle schema + local Postgres compose
│   └── ui/                # Shared React components
├── scripts/               # bootstrap.ts (provision + trim), seed via packages/service
├── package.json           # Root workspace scripts
├── turbo.json             # Turborepo pipeline + env
└── pnpm-workspace.yaml    # Workspaces + version catalog
```

## Applications (`apps/`)

### Web App (`apps/web/`)

Next.js 16 with the App Router:

```
apps/web/
├── content/
│   └── docs/              # These docs (fumadocs MDX)
├── src/
│   ├── app/
│   │   ├── (auth)/        # Login, register, password reset
│   │   ├── (dashboard)/   # Protected dashboard
│   │   │   └── dashboard/
│   │   │       ├── [slug]/    # Org pages: todos, members, settings, billing
│   │   │       └── account/   # User account settings
│   │   ├── (docs)/        # Docs routes (fumadocs)
│   │   ├── (marketing)/   # Public landing page
│   │   └── api/
│   │       ├── auth/[...all]/  # better-auth handler
│   │       ├── orpc/[[...rest]]/ # oRPC endpoint
│   │       ├── health/         # Liveness check
│   │       └── search/         # Docs search
│   ├── components/        # App-level components (header, nav, theme)
│   ├── lib/               # auth-client, site-config, fumadocs source
│   ├── orpc/              # oRPC client setup (react, server, query-client)
│   └── proxy.ts           # Markdown content negotiation for agents
├── next.config.ts
└── package.json
```

#### Route Conventions

- `(auth)/`, `(dashboard)/`, `(marketing)/`, `(docs)/` - route groups
- `[slug]/` - dynamic org routes
- `_components/` - colocated components, not routes

## Shared Packages (`packages/`)

### Contract Package (`packages/contract/`)

The API's single source of truth - what each procedure accepts, returns, and can fail with. Clients type against it without importing server code:

```
packages/contract/src/
├── organization/          # organization-contract.ts, organization-schema.ts
├── todo/                  # Example CRUD contract
├── waitlist/              # Waitlist contract
├── base.ts                # publicBase, protectedBase, organizationBase
└── index.ts               # Exports: contract, ContractClient, RouterInputs/Outputs
```

Convention per feature: `*-contract.ts` (procedures), `*-schema.ts` (Zod inputs).

### Service Package (`packages/service/`)

oRPC implementation of the contract, plus better-auth config:

```
packages/service/src/
├── auth/                  # auth.ts (better-auth), auth-schema.ts, utils
├── organization/          # organization-router.ts, -test
├── todo/                  # Example CRUD router
├── waitlist/              # Waitlist router
├── root-router.ts         # Implements the whole contract
├── orpc.ts                # Context, implementer, middleware
├── test-utils.ts          # node:test helpers
└── index.ts               # Exports: appRouter, AppRouter, createORPCContext
```

Convention per feature: `*-router.ts` (handlers), `*.test.ts` (tests).

### Auth Package (`packages/auth/`)

Client-safe auth helpers, imported by the server and by web and mobile clients alike:

```
packages/auth/src/
├── permissions.ts         # better-auth access control: ac, roles, hasPermission, ROLES, roleSchema
└── slug.ts                # slugify, FALLBACK_ORGANIZATION_SLUG
```

No server code (database, better-auth instance, secrets) belongs here.

### Database Package (`packages/db/`)

```
packages/db/
├── src/
│   ├── drizzle-schema.ts       # App tables (waitlist, todo)
│   ├── drizzle-schema-auth.ts  # better-auth generated tables
│   ├── drizzle-relations.ts    # defineRelations graph over both schema files
│   ├── drizzle-client.ts       # postgres.js + Drizzle client
│   └── index.ts                # Re-exports drizzle-orm operators
├── docker-compose.yml          # Local Postgres (postgres:18-alpine, $POSTGRES_PORT)
├── drizzle.config.ts
└── package.json                # db scripts (start, push, reset, studio)
```

### UI Package (`packages/ui/`)

shadcn-style components on Base UI (base-vega registry):

```
packages/ui/
├── src/
│   ├── components/        # Flat primitives
│   ├── hooks/
│   └── styles/globals.css
├── components.json        # shadcn config (style: base-vega)
└── postcss.config.mjs
```

Apps import explicit paths:

- `@repo/ui/components/<name>`
- `@repo/ui/globals.css`

Add components from the registry:

```bash
cd packages/ui && pnpm dlx shadcn@latest add <component>
```

## Documentation

No separate docs package - these pages are MDX files in `apps/web/content/docs/`, rendered by fumadocs (`apps/web/src/lib/source.ts`).

## Configuration Files

- `package.json` - Workspace scripts (`dev:web`, `db:push`, ...)
- `turbo.json` - Pipeline + `globalEnv` allow-list for env vars
- `pnpm-workspace.yaml` - Workspaces and the shared version catalog
- `.oxlintrc.json` - Linting (oxlint); formatting is oxfmt

## Key Design Principles

1. **Separation of concerns** - Apps own UX; packages own logic, data, and primitives
2. **Code sharing** - One oRPC router, one auth config, one schema for every platform
3. **Type safety** - Types flow from schema through API to UI, no codegen
4. **Explicit imports** - `@repo/ui/components/button`, not barrel files

## Adding New Features

### New API Routes

1. Add `packages/contract/src/<feature>/` with contract + schema, and register it in `packages/contract/src/index.ts`
2. Add `packages/service/src/<feature>/<feature>-router.ts` implementing it
3. Register in `packages/service/src/root-router.ts`
4. Consume with full types via the `orpc` utils

### New UI Components

1. Add to `packages/ui/src/components/` (or `pnpm dlx shadcn@latest add`)
2. Import as `@repo/ui/components/<name>`

### New Database Tables

1. Define in `packages/db/src/drizzle-schema.ts` with `pgTable.withRLS`
2. Run `pnpm db:push`
3. Types flow everywhere automatically
